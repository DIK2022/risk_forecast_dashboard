# Техническое задание: Risk Forecast Dashboard (десктопное приложение для прогнозирования временных рядов)

## 1. Цель проекта
Разработка десктопное приложение на **PySide6** для загрузки временных рядов (CSV), их визуализации (2D графика + опциональная 3D сцена) и прогнзирования с помощью двухматиматических моделей: экспоненциальное сглаживание и линейная регрессия по скользящему окну. Приложение предназначено для демонстарации навыков заказчикам.

## 2. Функциональные требования

### 2.1 Загрузка данных
- Поддержка CSV-файлов с колонками 'timestamp' (дата/время) и 'value' (числовое значение).
- Если колонка 'timestamp' отсутствует, использовать порядковый номер записи.
- Отображение данных в таблице (QTableView).
- Сохранение последнего использования пути к файлу (в настройках приложения).

### 2.2 Визуализация (2D)
- Использование **pyqtgraph** для отображения:
    - Исходного времени ряда (синяя линия + маркеры).
    - Сглаженного ряда (оранжевая линия) - только для экспоненциального сглаживания.
    - Прогноза (красная пунктирная линия) с доверительным интервалом (полупрозрачная зона).
- Интерактивность: зум, панорамирование, подписи осей, легенда.

### 2.3 Управление моделью прогноза
Параметры доступные пользователю:
- **Методы прогноза** (QComboBox):
    - Экспоненциальное сглаживание (α)
    - Линейная регрессия по скользящему окну (размер окна)
- **Горизонт прогноза** (QSpinBox: 1..50 шагов)
- **Параметры α** (QSpinBox: 0.05..0.95, шаг 0.05) - активен для первого метода
- **Размер окна** (QSpinBox: 5..100) - активен для второго метода
- Кнопка **"Рассчитать"** (запуск пррогноза в отдельном потоке)

При изменении любого параметра прогноза пересчитывается автоматически (или по кнопке - на усмотрение).

### 2.4 Экспорт
- Сохранение текущего графика в **PNG** (через метод pyqtgraph 'exportImage').
- Экспорт отчёта в **PDF**:
    - Заголовок (дата, название метода, параметры)
    - Таблица прогнозных значений (шаг, прогноз, нижняя граница, верхняя граница)
    - Встроенное изображение графика (из PNG)

### 2.5 Опционально - 3D виртуализация (бонус)
- Вкладка "3D" с простой сценой (цилиндр или куб).
- Цвет объекта меняется от зелёного к красному в зависимости от последнего прогнозного значения (нормированного на максимум).
- Использование 'vispy' или 'PyOpenGL' + встраивание в PySide6.

## 3. Архитектура и паттерны

### 3.1 Общая архитектура - MVC (Model-View-Controller)
- **Model** - данные, алгоритмы прогнозирования, экспорт, обновление. Не содержит Qt-импортов (кроме сигналов).
- **View** - загрузка '.ui' файла, виджеты, сигналы о действиях пользователя. Не содержит бизнес-логики.
- **Controller** - связывает Model и View, обрабатывает сигналы, запускает потоки.

### 3.2 Используемые паттерны
- **Strategy** - для алгоритмов прогнозирования (базовый класс 'ForecastStrategy', наследники 'ExponentialSmoothingStrategy', 'RollingRegressionStrategy').
- **Observer** - сигналы Qt: 'data_loaded', 'forecast_updated', 'status_message'.
- **Worker Thread** - 'QThread' для асинхронного расчета прогноза (не блокировать GUI).
- **Factory** (опционально) - для создания экспортёров (PNG, PDF).
- **Singleton** - для глобальных настроек приложения (последний путь, параметры интерфейса).

## 4. Интерфейс пользователя (UI)

### 4.1  Контейнер - QTabWidget (4 вкладки)
1. **Данные** - QTableView + кнопка "Загрузить CSV".
2. **График** - виджет pyqtgraph.
3. **Модель** - панель с QComboBox, QSlider, QSpinbox, QPushButton.
4. **3D** (опционально) - контейнер для Vispy/OpenGL.


### 4.2 Проектирование UI
- Используется **Qt Designer** (файл 'ui/main_window.ui).
- Генерация Python-класса через 'pyside6-uic'.
- Все виджеты имеют осмысленные 'objectName' для доступа из контроллера.

## 10. Приложение: пример данных (генератор)
Файл `generate_data.py` создаёт CSV с трендом, суточной/недельной сезонностью, шумом и выбросами. Сохраняет в `data/sensor_data.csv`.

```python
import numpy as np
import pandas as pd

np.random.seed(42)
n_points = 2000
dates = pd.date_range("2022-01-01", periods=n_points, freq="H")
trend = np.linspace(50, 80, n_points)
daily = 10 * np.sin(2 * np.pi * np.arange(n_points) / 24)
weekly = 5 * np.sin(2 * np.pi * np.arange(n_points) / 168)
noise = np.random.normal(0, 2, n_points)
outliers = np.zeros(n_points)
outlier_idx = np.random.choice(n_points, size=int(0.02 * n_points), replace=False)
outliers[outlier_idx] = np.random.uniform(30, 60, size=len(outlier_idx))
value = trend + daily + weekly + noise + outliers
value = np.clip(value, 20, 150)
df = pd.DataFrame({"timestamp": dates, "value": np.round(value, 2)})
df.to_csv("data/sensor_data.csv", index=False)
```

## 11. Автоматическое обновление (из Git) – подробности

Почему Git, а не релизы?
На этапе разработки и внутреннего тестирования проще использовать git pull. Это не требует настройки дополнительной инфраструктуры (сервер релизов, цифровые подписи). Пользователи должны иметь доступ к репозиторию и установленный Git.

###Алгоритм работы:
1. Приложение при запуске (или по нажатию кнопки) вызывает GitUpdater.check_for_updates().
   Выполняется git fetch и сравнение HEAD с @{u}.
2. Если обновления есть, появляется QMessageBox.question с предложением обновиться.

3. При согласии пользователя:
    - Выполняется git pull --ff-only (только fast-forward).
    - В случае успеха – вызов os.execl() для перезапуска приложения.
    - В случае ошибки (конфликт, нет сети) – сообщение пользователю.

###Ограничения подхода:
    - Пользователь должен иметь Git в PATH.
    - Репозиторий должен быть клонирован с правами на запись (если git pull требует пароль/токен, придётся настроить SSH или хранить токен в конфиге – для пет-проекта обычно хватает SSH-ключа).
    - Не подходит для распространения через .exe (там код запакован). В будущем для релизов перейти на обновление через GitHub Releases.

###Класс GitUpdater (разместить в src/models/updater.py):
```python

import subprocess
import sys
import os
from pathlib import Path

class GitUpdater:
    def __init__(self, repo_path: Path):
        self.repo_path = repo_path

    def check_for_updates(self) -> bool:
        try:
            subprocess.run(['git', 'fetch'], cwd=self.repo_path, check=True, capture_output=True)
            local = subprocess.run(['git', 'rev-parse', 'HEAD'], cwd=self.repo_path, capture_output=True, text=True, check=True).stdout.strip()
            remote = subprocess.run(['git', 'rev-parse', '@{u}'], cwd=self.repo_path, capture_output=True, text=True, check=True).stdout.strip()
            return local != remote
        except subprocess.CalledProcessError:
            return False

    def perform_update(self) -> bool:
        try:
            subprocess.run(['git', 'pull', '--ff-only'], cwd=self.repo_path, check=True)
            return True
        except subprocess.CalledProcessError:
            return False

    def restart_application(self):
        python = sys.executable
        os.execl(python, python, *sys.argv)```
